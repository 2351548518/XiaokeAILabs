# 自己复现：环境配置记录

本文记录 2026-10-23 为文本训练配置 Python 环境的步骤，以及依赖和 GPU 的合成运算检查结果。
尚未验证完整模型训练、数据准备、真实训练显存或多卡通信；不能据此引用训练效果或吞吐指标。
本配置与历史报告中的 GB10 环境分开记录。

`nvidia-smi` 能看到显卡不足以判定训练可用，仍需执行 PyTorch 运算检查。

## 2. 配置文件

以下路径均相对于本实验目录 `experiments/jev-open-source/`，不是整个仓库的根目录。

| 文件 | 作用 |
|---|---|
| [requirements.txt](../requirements.txt) | 引用文本训练依赖，并固定本次使用的直接依赖版本 |
| [text_jev_train/requirements.txt](../text_jev_train/requirements.txt) | 文本训练脚本的基础依赖要求 |
| [uv.toml](../uv.toml) | 为 `uv pip` 指定 `cu128` 后端，从官方 PyTorch 源获取对应构建 |
| [.python-version](../.python-version) | 选择 Python 3.12 |
| [test_env.py](../test_env.py) | 检查 `.venv`、文本依赖、Qwen3 接口与 GPU 运算 |

直接依赖固定如下，具体内容以 `requirements.txt` 为准：

```text
torch==2.10.0+cu128
transformers==5.20.2
numpy==2.5.4
pyarrow==26.0.0
huggingface_hub==2.2.0
requests==2.34.2
packaging==26.3
```

`packaging` 用于环境检查脚本解析版本要求。`torch` 中的 `+cu128` 固定 CUDA 构建，
配合下面的 `uv.toml` 配置，避免再次选中 CUDA 13 或 CPU 构建：

```toml
[pip]
torch-backend = "cu128"
```

这里固定的是直接依赖，不是包含所有传递依赖的完整锁文件。
本配置面向文本训练；视觉训练和其他模型部署仍需查看对应目录的依赖说明。

## 3. 使用 uv 配置环境

以下命令使用 Bash，均在本实验目录执行。先确认 `uv` 和 NVIDIA 驱动可用：

```bash
uv --version
nvidia-smi
```

首次创建环境时执行；已有 `.venv` 时跳过创建步骤：

```bash
uv venv --python 3.12 .venv
```

安装依赖，并保留终端输出：

```bash
mkdir -p docs/执行日志
set -o pipefail
uv pip install --python .venv/bin/python -r requirements.txt --no-progress \
  2>&1 | tee docs/执行日志/自己复现-环境安装.log
uv pip check --python .venv/bin/python \
  2>&1 | tee docs/执行日志/自己复现-依赖检查.log
```

`--python` 显式指定目标环境，因此安装时无需先激活 `.venv`。
本次 `uv pip check` 的结果为 `All installed packages are compatible`。
日常使用可以激活环境：

```bash
source .venv/bin/activate
python --version
```

## 4. 验证 GPU 是否真正可用

运行完整环境检查：

```bash
set -o pipefail
.venv/bin/python test_env.py \
  2>&1 | tee docs/执行日志/自己复现-GPU环境检查.log
```

脚本默认检查逻辑设备 `cuda:0`，成功退出码为 `0`，失败为 `1`。检查内容包括：

- 文本训练依赖的版本和实际导入，以及 `Qwen3Model` 等接口。
- CUDA 初始化、GPU 型号、计算能力、可见设备数和当前剩余显存。
- NumPy 到 PyTorch 的转换、GPU FP32 矩阵运算及同步。
- 随机初始化的微型 Qwen3 的 BF16 前向、反向传播、梯度裁剪和 AdamW 参数更新。

检查不下载模型或训练数据。指定另一张可见显卡时使用：

```bash
.venv/bin/python test_env.py --device 1
```

设备编号遵循 `CUDA_VISIBLE_DEVICES`。例如仅暴露物理 GPU 3 后，它在进程中编号为 `cuda:0`：

```bash
CUDA_VISIBLE_DEVICES=3 .venv/bin/python test_env.py --device 0
```
