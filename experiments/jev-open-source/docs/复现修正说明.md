# 复现链路修正与历史结果边界

本篇记录代码复核后修正的实现问题、需要重建的产物及回归检查范围。未进行完整模型训练或 GPU 性能重测；不能引用本篇作为准确率提升或新性能结论。

## 修正内容

- 文本训练将初始化也保存为候选 checkpoint，训练无提升时仍能加载并校准；最后一步也参与 dev 选优，短运行不再遗漏评估。
- 视觉训练补齐优化器更新，显式启用训练模式，按问题平均损失，首步学习率非零；更新前后检查内存，覆盖 Adam 首步分配状态的情况。检查属于采样保护，无法保证阻止操作内部 OOM。
- 视觉训练、评测、服务共用图像预处理和温度契约。模型运行器只返回原始 logits，统一执行一次 `softmax(logits / T)`；独立评测复用原始 logits，避免重复前向。
- 温度在训练时存入 adapter 目录，独立评测导出到评测目录。服务支持显式加载评测文件；没有温度文件时不再自动当作已校准成功，需显式选择 `--temperature 1`。
- ScienceQA 的 `lecture`、`solution`、`answer` 不进入输入；`answer` 只生成监督目标。图片统一编码后去重，再按 seed 哈希排序做约 60/10/10/20 的自定义划分，替代无法满足的固定配额。
- Laya 与 metask 共用分类题集、任务指令和类别描述，打印 `ticket-classification-v2`。模型自己的模板仍不同，Nimble 和 Qwen 的测试范围也没有因此变成相同任务。
- metask 校准配置按脚本位置读取，启动目录不再影响温度。RLCD A/B 使用当前解释器、公开依赖检查与可配置路径，保存终端日志并传播任一训练臂的失败。

新增的代码注释主要解释这些边界：为什么初始化也要落盘、为什么 logits 必须保持原始尺度、为什么答案解析不能进入输入，以及内存检查与优化器更新的先后关系。

## 旧产物如何处理

旧日志保留其原始数值，未用修正后的代码反向改写。Laya 与 metask 历史分类样本只有 15/20 组完全相同，类别描述也不同，因此旧准确率不支持严格的模型排名。

视觉旧输入含答案解析、训练脚本缺少参数更新、独立评测重复应用温度，旧交接表不能作为修正后训练或校准的验收目标。需在训练机重新准备数据、训练并评测。新输入格式为 `scienceqa.question_only.v2`，训练与评测拒绝无此标记的旧 prepared 文件；自定义 test 划分不等于 ScienceQA 官方测试协议。

当前视觉训练保存最后一次更新，不做 dev checkpoint 选优；`protocol.json` 与 README 已据此修正。文本训练仍按 dev 选优。两个训练入口的职责不同。

## 回归检查

需要 CPU 版 torch、numpy、Pillow 与 pytest，不下载模型或真实数据：

```bash
set -o pipefail
PYTHONDONTWRITEBYTECODE=1 python -m pytest tests/test_regressions.py -q -p no:cacheprovider \
  2>&1 | tee docs/执行日志/18-代码回归检查.log
bash -n laya_rlcd_train/scripts/run_ab_compare.sh
```

测试使用临时目录，覆盖真实 autograd/AdamW 参数更新、更新后内存退出、评测与服务概率一致、旧输入拒绝、去重切分、初始化及最终步选优、配置路径和 A/B shell 失败传播。微型网络替代预训练模型，不能证明真实 CUDA 底座、LoRA 集成或吞吐已经验证通过。
